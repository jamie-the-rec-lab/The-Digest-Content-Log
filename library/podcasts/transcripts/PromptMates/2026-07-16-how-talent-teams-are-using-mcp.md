## Actionable summary
**Guest:** Matt Texeira, Global Talent Director and AI Transformation at Komodo Health, a Greenhouse MCP design partner, with a live demo from Quadri, senior product manager at Greenhouse, and hosts Jason and Joe.  ·  **Show:** PromptMates, 16 Jul 2026
**Tags:** mcp, claude skills, ats integration, recruiting operations, data governance, ai agents

**When to use this:** You want to connect your ATS to an LLM to run recruiter workflows but worry about security, permissions and PII.

**Big idea:** An MCP is standardised plumbing, like a USB port, that lets AI take actions in your systems, and a vendor-built one beats a homemade GitHub version because it carries governance and permission gating your own build cannot.

**Frameworks & plays:**
- Matt defines MCP as Model Context Protocol giving AI three things: tools (actions like search candidates or move stages), resources (data and records) and prompts; it wraps APIs rather than replacing them and is a tiny JSON file in your Claude config.
- Greenhouse's MCP, in free open beta, exposes over 150 tools that site admins approve; from August it becomes permission-gated so team members only see and act on what their Greenhouse permissions allow.
- Matt builds Claude skills at Komodo for repeat jobs: debrief prep, rec deep dive and TLDR pipeline, plus a context skill that accounts for his messy ATS org structure and IDs so every skill has clean data.
- Matt runs a daily Claude Code build with four agents (compensation, interview, brand, intel) scraping 19 signals from Greenhouse and Glean, flagging comp issues he forwards to hiring managers with cited sources.
- An interview-prep agent uses the Greenhouse MCP plus scorecards and resumes to send each interviewer a morning Slack with who they are seeing, their role in the process and bias reminders.

**Data & benchmarks:**
- Jason reports roughly 8 to 8.5 cents per resume using Sonnet 4.6, so reading 100 candidates costs about 8 dollars.

**Contrarian take:**
- Matt and Jason built the first enterprise-grade Greenhouse MCP, put it on GitHub, then took it down in a panic because it made it too easy to pull sensitive data into LLMs, which is why they now advocate vendor partnership; Matt also argues not every recruiter needs to be a builder.

**Steal this (do tomorrow):**
- Turn off demographic and EEOC data in your MCP tool exposure so it is blocked, not just unused.
- Build one repeat workflow, like debrief prep, as a skill you invoke with a single loose sentence.

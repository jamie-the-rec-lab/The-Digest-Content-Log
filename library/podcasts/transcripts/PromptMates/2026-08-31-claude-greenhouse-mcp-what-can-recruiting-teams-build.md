## Actionable summary
**Guest:** Matt Texeira, Senior Director of Global Talent Acquisition at Komodo Health, who has built a set of Claude Skills on top of the Greenhouse MCP for his own recruiting team  ·  **Show:** PromptMates, 31 Aug 2026
**Tags:** claude code, ai agents, building ai tools, recruiting operations, recruiter productivity, rec tech, human-ai collaboration

**When to use this:** you have MCP access to your ATS turned on but no idea what a recruiter, not an engineer, should actually build with it on day one.

**Big idea:** the value of Claude connected to your ATS comes from turning repeat recruiter tasks into named skills, not from one-off prompting or ambitious agent builds.

**Frameworks & plays:**
- Build a "context" skill first that teaches Claude the mess in your own ATS instance (org structure, cost centres, custom fields, recruiter IDs) so every other skill it runs corrects for that nuance before producing output.
- Build a debrief prep skill that pulls scorecards, round-by-round signals, cross-interview synthesis, strengths, contradictions, rating distribution and outstanding scorecards, then generates discussion prompts for the panel.
- Build a lighter "TLDR pipeline" skill that returns quick funnel counts for a role, for when you just need headline numbers before a hiring manager sync rather than the full deep dive.
- Feed a meeting transcript in and ask Claude to open a new requisition in Greenhouse, clone an existing one, draft suggested interview questions for the panel and surface silver medallists from a past search for the same role, all in one multi-step prompt.
- Set up a daily Slack digest that pulls each day's interviewers their candidate's time in process, discussion focus areas and bias reminders directly from the interview kit, so people who are back to back still get prepped.
- Judge debrief quality by whether interviewers actually evaluated the attributes the scorecard said mattered, not by whether the resume matched a rubric.

**Tools & prompts:** 
- Runs everything in Sonnet rather than Opus for cost efficiency, and says a well-built skill lets the prompt itself stay vague, for example simply "heading into a debrief for this applicant at 2pm, how are things going?"
- A more advanced build uses Claude Code agents that scrape 19 signals from Greenhouse plus company context from a Glean MCP connection into Slack, split into four agents (compensation, interview, brand, intel) that flag issues like a comp mismatch daily, citing the exact Greenhouse source for each claim.

**Steal this (do tomorrow):**
- Turn your most repeated ATS task, such as debrief prep or a pipeline TLDR, into one named skill rather than re-prompting from scratch each time.
- Explicitly block sensitive fields such as EEOC and demographic data from MCP access rather than assuming it stays out by default.

## Actionable summary
**Guest:** Josh (surname not given), recruiting operations at Luma, building a live Claude Code demo for PromptMates  ·  **Show:** PromptMates, 16 Oct 2026
**Tags:** ai agents, claude code, building ai tools, recruiter workflow, recruiting operations, recruiter productivity, hiring manager alignment, scorecards, context engineering

**When to use this:** hiring managers and interviewers keep asking you where a role or candidate stands and you are copying data between your ATS, interview tool and Slack to answer.

**Big idea:** Rather than a 30 or 40 step workflow, give Claude Code the APIs of your recruiting stack as tools and let it decide which to use, then expose it as a Slack slash command.

**Frameworks & plays:**
- Start from the output you want and work backwards to the tools it needs. His output was a status report on a role, triggered by a Slack slash command he calls /chase, for either a role or a candidate.
- Give the agent a toolbox rather than a script. He wrote tools over the Ashby API (jobs, applications, scorecards, interviews, activity) and the Metaview API (transcripts), plus Slack search, and told the model what each tool is for.
- Set the goal in the prompt as: find everything stuck in this pipeline for this role, work out why, and say how to solve it. Tell the model it can loop until it has a confident result and keep the reply under a set word count. He used Claude Opus for extra capability.
- Plan before building. He starts in plan mode about 99% of the time and talks the use case through by voice to text (he named Whisper Flow) so Claude can structure it.
- Ship in small steps: Claude Code opened a pull request, he reviewed it as a non-engineer in GitHub and merged each part, with the repo on GitHub and hosting on Vercel set up beforehand.
- Ask the agent to show its working in the Slack thread. His showed it finding the job, pulling applications and activity, then each interview, scorecard and transcript, capped at five candidates (adjustable to 10 or 15).
- Get Slack admin help early. Slack apps usually need engineering approval, so recruit a Slack admin or ask for a lower app-manager role.

**Data & benchmarks:**
- In the demo the report on a senior product engineer role found three active candidates, all stalled, and flagged that no application had a note so stuck time could not be measured. It also flagged that one interview loop had two scorecards submitted and one missing.
- A runtime of roughly two minutes per request was normal.

**Tools & prompts:**
- Claude Code (Mac app), GitHub, Vercel, Slack app with a slash command, Ashby API, Metaview API, CodeSignal mentioned as a connected source.

**Contrarian take:**
- He argued against building it as a rigid checklist workflow and in favour of letting the model choose tools, because it may skip Metaview when Ashby already answers the question.

**Steal this (do tomorrow):**
- Write down the three questions hiring managers ask you most often and the systems each answer lives in, then draft the prompt as goal, tools, loop rule and length limit.
- Climb the ladder he suggests: Claude chat, then Cowork with scheduled tasks, then Claude Code and routines, which run without your laptop being on.

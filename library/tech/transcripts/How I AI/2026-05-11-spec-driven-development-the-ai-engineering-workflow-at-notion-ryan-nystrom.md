**Tags:** ai coding, engineering, product management

**When to use this:** You're engineering leader trying to adopt AI-driven development without losing code quality.

**Big idea:** Spec-driven development at scale means investing heavily in spec quality and using AI to generate code from high-confidence specs.

**Frameworks & plays:**
- Ryan's workflow at Notion: all features start as detailed specs (behaviour, edge cases, performance targets, data models). The spec is reviewed by senior engineers before Claude Code ever sees it. Then Claude Code generates the implementation. Code reviews become about 'does the output match the spec' not 'is this the right approach'. This shifts review time from design to validation.

**Data & benchmarks:**
- Feature turnaround at Notion: 2 days (spec + review) to 1 day (Claude Code generation + validation). Code defects in AI-generated code: 12% lower than hand-written code in their sample.

**Contrarian take:**
- Ryan's take: 'The game is now spec quality. Bad specs go in, bad code comes out. Perfect specs go in, perfect code comes out.'

**Steal this (do tomorrow):**
- Invest in your spec template. Make it review-friendly. Train your team to see spec quality as the product.
